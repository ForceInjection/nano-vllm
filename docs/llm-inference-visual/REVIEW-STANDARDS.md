# Slide 评审标准

基于 L01、L02 两轮完整校对总结，用于后续章节评审。

---

## 1. 编号规则

### 1.1 节编号与教案严格一致

PPT 中出现的任何节编号，**必须在教案（参考文档）中存在**。教案没有的编号，PPT 不能有。

| 规则             | 说明                                                 |
| ---------------- | ---------------------------------------------------- |
| 教案有的编号     | PPT 必须原样出现                                     |
| 教案没有的子编号 | PPT 不能自创（如 `2.1.1`、`3.3.1` 等，除非教案有）   |
| 节分隔页         | `# 2. 原理说明`、`# 3. 代码走读`、`# 4. 验证脚本` 等 |

```text
反例：教案只有 2.1、2.2，PPT 自创了 2.1.1 → 禁止
正例：教案有 3.3.1、3.3.2，PPT 保留 3.3.1、3.3.2 → 允许
```

### 1.2 子 slide 不编号

同一个父节下有多页展开时，**仅首个 slide 带编号**，后续 slide 只保留标题文字。

```text
3.3 step：三段式总览       ← 首 slide 带编号
三段式的数据流              ← 续 slide 无编号（图解页）
```

### 1.3 教案无对应节的 slide 不编号

PPT 中有但教案中没有独立节的 slide，去掉编号。

```text
反例：教案无 3.5，PPT 有 # 3.5 num_tokens → 禁止
正例：# num_tokens 的符号 → 允许（无编号）
```

## 2. 代码准确性

### 2.1 内联代码与源码一致

每个 ` ```python ` 代码块必须与仓库源文件对比，逻辑一致、变量名一致。

- 可以省略类型标注、默认参数（教学简化）
- 不能改变控制流逻辑
- 简化版代码如果与源码风格不同，优先改为与源码一致
- `sampling_params=None` 这类会导致 `AttributeError` 的错误严格禁止

### 2.2 SourceCode 行号准确

`<SourceCode file="..." lines="X-Y" />` 的行号范围必须覆盖展示的代码。

- 如果展示代码跨不连续行，去掉 SourceCode 引用比标错行号好
- 代码块内新增的教学注释不影响行号准确性

### 2.3 代码注释与动画标记

带编号注释的代码块（①②③④），需满足：

1. **每个编号只出现一次**，标注在最关键的那一行
2. **Slidev 动画标记** `{all|...|...}` 的行号范围必须与实际代码行数精确对应
3. **每个动画步只覆盖该编号的逻辑范围**——不吞并相邻步骤的代码，不漏掉本步骤的 break/return
4. 底部信息框的编号与代码注释编号一一对应

```text
反例：{all|5-7|8-11|12-14} ← 5-7 覆盖了②的起始行，12-14 漏了break行
正例：{all|5-6|7-13|14-15} ← 每个编号精确覆盖自己的 if+break/results
```

#### 2.3.1 动画步的"最小逻辑单元"原则

每个编号对应一个不可再分的逻辑动作，动画范围应恰好覆盖该动作：

| 代码模式                          |      动画范围      | 说明                       |
| --------------------------------- | :----------------: | -------------------------- |
| `if cond: / break`                |  2 行（if+break）  | 一个退出条件 = 判断 + 退出 |
| `if cond: / action / else: / alt` |  整个 if/else 块   | 完整判断分支               |
| `return ...`                      | 从 return 行到结束 | 不包含上一步的 append      |
| for 循环体（多行）                 |   整个循环体范围   | 包括 for header + 所有 body 行 |

#### 2.3.2 信息框标题不合并编号

代码注释中 ①②③④ 各自独立，信息框标题也应对应独立编号，**禁止**用 "①② xxx" 这种合并写法。

```text
反例：<strong>①② used_block_ids 检查</strong>  ← 合并了两个编号，读者困惑
正例：<strong>① 命中后：共享 vs 重新取出</strong>  ← 以首个编号定位，其余在内容中独立说明
```

### 2.5 集合类型与构造函数参数准确性

代码块中的类型标注（`set` vs `deque`）、构造函数参数（`Block(i)` vs `Block(i, block_size)`）必须与源码一致。即使是"概念示意"代码，也不能使用与源码不兼容的类型。

```text
反例：self.free_block_ids: set[int] = set(range(num_blocks))  ← 源码用 deque，popleft 不兼容
正例：self.free_block_ids: deque[int] = deque(range(num_blocks))
```

### 2.4 变量名一致性

**同一源文件的同一变量，在所有代码块中必须使用相同名称**。禁止为缩短行宽而使用缩写（如 `n` 替代 `num_cached_blocks`），除非源码本身使用了缩写。

- 如果一个代码块使用了缩写而另一个使用了全名 → 统一为源码名称
- 如果源码本身使用缩写 → 可以保持缩写

## 3. 代码 + 信息框模式

凡是有代码块的 slide，必须配套：

| 元素     | 位置               | 样式                          | 内容               |
| -------- | ------------------ | ----------------------------- | ------------------ |
| 编号注释 | 代码行尾           | `# ① xxx`                     | 关键动作标注       |
| 总览框   | 代码下方           | `bg-green-500/10 border-l-3`  | 所有步骤一句话总结 |
| 点睛框   | 总览框下方（可选） | `bg-yellow-500/10 border-l-3` | 最关键的一句话总结 |

示例结构：

```text
代码块（①②③④ 编号注释）
  ↓
🟢 绿色框：N 个步骤总览
  ↓
🟡 黄色框：关键要点的人话总结（可选）
```

### 3.1 适用范围

代码+信息框模式不仅适用于 §3（代码走读），**§4 验证脚本中的代码页同样适用**。任何包含可运行代码的 slide 都应配绿色总览框。

## 4. 文本框样式规范

### 4.1 色框使用场景

| 颜色 | 场景               | 类名                                            |
| ---- | ------------------ | ----------------------------------------------- |
| 绿色 | 总结、观察、好处   | `bg-green-500/10 border-l-3 border-green-500`   |
| 黄色 | 注意、警告、约束   | `bg-yellow-500/10 border-l-3 border-yellow-500` |
| 蓝色 | 引导、验证、承接   | `bg-blue-500/10 border-l-3 border-blue-500`     |
| 紫色 | 关键结论、联动规则 | `bg-purple-500/10 border-l-3 border-purple-500` |

### 4.2 文字样式

- 引导语/结论文字不要用 `opacity-*` 淡化，应使用色框突出
- `text-xs` 仅用于脚注或极次要信息
- 信息框正文用 `text-sm`，代码块内的注释保持默认

## 5. 演讲注释（Speaker Notes）

### 5.1 每页必须有

每个 slide（包括无编号的子 slide）都必须有 `<!-- ... -->` 演讲注释。

### 5.2 内容准确

- 注释必须描述**当前 slide** 的内容，不能是其他 slide 的
- 不能包含编辑指令（如"合并两个紫色框"）
- 不能有重复注释（如结束页两条几乎一样的注释）
- 引用源文件行号必须与 SourceCode 标签一致

### 5.3 反例

```text
<!-- 本页用表格展示 status 和 is_prefill... -->  ← 描述的是上一页内容
<!-- 合并两个紫色框，提炼联动规则... -->          ← 编辑指令，不是演讲内容
```

## 6. 图解页排版

### 6.1 Mermaid 图居中与闭合

````html
<div class="flex justify-center">```mermaid {scale: 0.7} ... ```</div>
````

**关键**：mermaid 代码块的闭合 ` ``` ` **必须在 `</div>` 之前**，否则 Vue 编译器报 `Element is missing end tag`。

### 6.2 复杂流程图的拆分

当 mermaid 图超过 ~12 个节点时，考虑拆分为多张聚焦子图：

- 每张子图只展示一个阶段（如 prefill 分支 / decode 分支）
- scale 从 0.3 提升到 0.55+，保证可读性
- 每张子图配独立的绿色总结框
- 教案中的完整流程图可作为参考，但 PPT 中不强制完整呈现

### 6.3 概念聚焦页

概念聚焦页（如 "概念 1：Chunked Prefill"）不编号，标题直接描述概念。

### 6.4 隐形边强制纵向排列

当 mermaid 图中多个独立根节点被默认排成一行（横向过宽）时，用 `~~~` 隐形边将它们链成纵向：

```mermaid
flowchart TD
    A --> A1
    B --> B1
    C --> C1
    A ~~~ B ~~~ C        ← 强制 A→B→C 纵向排列
```

### 6.5 2×2 网格展示多个小图

当需要并排展示多个独立的小型 mermaid 图时，使用 `grid grid-cols-2`：

```html
<div class="grid grid-cols-2 gap-4 mt-4">
<div>
<h4 class="text-sm font-bold mb-1 text-center">方法名</h4>
<div class="flex justify-center">

```mermaid {scale: 0.85}
flowchart TD
    A["入口"] --> B["步骤1"]
    A --> C["步骤2"]
```

</div>
</div>
<!-- 重复 4 次组成 2×2 -->
</div>
```

每个格子内 mermaid 用小 scale（0.85），标题 `text-center` 居中。

## 7. 内容去重

### 7.1 代码走读与验证脚本之间

第 3 节（代码走读）和第 4 节（验证脚本）容易出现内容重复。处理方式：

- 保留代码走读中的完整内容
- 验证脚本中 **去掉重复的输出表/公式**，改为一行引用指回代码走读

```text
反例：§2 页重复输出与 3.4 快速验证一模一样的表格
正例：§2 页保留代码，用一行 "📍 运行结果参见 3.4 快速验证" 替代重复表格
```

### 7.2 代码块与信息框之间

信息框是对代码的"人话总结"，不应与代码注释完全重复。代码注释是操作层面的（"做了什么"），信息框是理解层面的（"为什么这样做 / 关键点是什么"）。

## 8. 纵向空间控制

### 8.1 单页代码上限

一个 slide 的代码块不超过 ~15 行。超过时：

1. **按逻辑边界拆分**：如 prefill 循环按"上半段判断 / 下半段执行"拆为两页
2. **去掉冗余展示**：已经在前面出现过的代码不再重复展示
3. **合并同类信息**：两个表达相同意思的框合并为一个

### 8.2 一页最多一张表格

包含表格的 slide，表格是核心元素，不应在同一页再放第二张表格。多表格场景用拆分或左右并排（grid-cols-2）解决。

### 8.3 左右并排适用条件

`grid-cols-2` 左右并排适用于：

- 两张结构相似、都较小的表
- 两张结构不同但都窄于半宽的表
- 不适合列数多、文字长的表

### 8.4 去掉冗余代码块

解释页（如 "为什么只登记完整 block？"）不应重复展示上一页已有的完整代码。去掉冗余代码块，只保留解释性文字和关键示例。

```text
反例：hash_blocks 解释页重复展示与 3.5 完全相同的 11 行代码 + 例子 → 22 行溢出
正例：用一行文字引用 start/end 机制 + 例子 + 安全说明 → 12 行
```

## 9. 构建与提交

### 9.1 先构建，后提交

**每次修改 slides 后，必须先在 slides 目录下执行构建验证：**

```bash
cd docs/llm-inference-visual/slides
npx slidev build --base ./
```

构建通过（`✓ built in X.XXs`）才能提交。构建失败则修复后重新构建。

常见构建失败原因：

- Mermaid 代码块 ` ``` ` 闭合缺失 → `Element is missing end tag`
- HTML 标签未闭合
- 动画标记行号超出代码块实际行数

### 9.2 构建命令路径

构建必须在 `docs/llm-inference-visual/slides/` 目录下执行（`package.json` 所在目录），从仓库根目录执行会报 404。

### 9.3 提交前回退无关修改

Slidev 项目的 linter 可能在构建时自动修改无关文件（如 slides.01.md 的对齐空格）。提交前用 `git checkout <unrelated-file>` 回退这些修改，只保留目标文件的改动。

## 10. 评审检查清单

逐 slide 检查时使用：

- [ ] 编号存在于教案中？
- [ ] 代码与源文件一致？（变量名、控制流、行号）
- [ ] 代码块间变量名一致？（无相同变量用不同名称）
- [ ] SourceCode 行号覆盖展示代码？
- [ ] 动画标记 `{all|...}` 行数正确、每个编号范围精确（含最小逻辑单元）？
- [ ] 代码注释编号每个只出现一次？
- [ ] 信息框标题不合并编号（无 "①② xxx" 写法）？
- [ ] 信息框与代码注释编号对应？
- [ ] 演讲注释描述的是当前 slide？
- [ ] 内容在第 3/4 节之间无重复？
- [ ] Mermaid 图居中、闭合 ` ``` ` 在 `</div>` 之前？
- [ ] 多个独立根节点的 mermaid 是否用 `~~~` 强制纵向排列？
- [ ] 复杂流程图是否拆分为多张子图（≤12 节点）？
- [ ] 解释页是否去掉了上一页已有的冗余代码？
- [ ] 单页代码 ≤15 行？
- [ ] 单页表格 ≤1 张？
- [ ] 无 `opacity-*` 淡化的关键文字？
- [ ] 提交前回退了 linter 对无关文件的修改？
- [ ] 构建通过（`npx slidev build --base ./`）？
