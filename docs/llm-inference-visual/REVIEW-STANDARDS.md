# Slide 评审标准

基于 L01、L02 两轮完整校对总结，用于后续章节评审。

---

## 1. 编号规则

### 1.1 节编号与教案严格一致

PPT 中出现的任何节编号，**必须在教案（参考文档）中存在**。教案没有的编号，PPT 不能有。

| 规则 | 说明 |
|------|------|
| 教案有的编号 | PPT 必须原样出现 |
| 教案没有的子编号 | PPT 不能自创（如 `2.1.1`、`3.3.1` 等，除非教案有） |
| 节分隔页 | `# 2. 原理说明`、`# 3. 代码走读`、`# 4. 验证脚本` 等 |

```
反例：教案只有 2.1、2.2，PPT 自创了 2.1.1 → 禁止
正例：教案有 3.3.1、3.3.2，PPT 保留 3.3.1、3.3.2 → 允许
```

### 1.2 子 slide 不编号

同一个父节下有多页展开时，**仅首个 slide 带编号**，后续 slide 只保留标题文字。

```
3.3 step：三段式总览       ← 首 slide 带编号
三段式的数据流              ← 续 slide 无编号（图解页）
```

### 1.3 教案无对应节的 slide 不编号

PPT 中有但教案中没有独立节的 slide，去掉编号。

```
反例：教案无 3.5，PPT 有 # 3.5 num_tokens → 禁止
正例：# num_tokens 的符号 → 允许（无编号）
```

## 2. 代码准确性

### 2.1 内联代码与源码一致

每个 ` ```python ` 代码块必须与仓库源文件对比，逻辑一致、变量名一致。

- 可以省略类型标注、默认参数（教学简化）
- 不能改变控制流逻辑
- 简化版代码如果与源码风格不同，优先改为与源码一致
- `sampling_params=None` 这类会导致 `AttributeError` 的错误严格禁止

### 2.2 SourceCode 行号准确

`<SourceCode file="..." lines="X-Y" />` 的行号范围必须覆盖展示的代码。

- 如果展示代码跨不连续行，去掉 SourceCode 引用比标错行号好
- 代码块内新增的教学注释不影响行号准确性

### 2.3 代码注释与动画标记

带编号注释的代码块（①②③④），需满足：

1. **每个编号只出现一次**，标注在最关键的那一行
2. **Slidev 动画标记** `{all|...|...}` 的行号范围必须与实际代码行数精确对应
3. 底部信息框的编号与代码注释编号一一对应

```
正例：
```python {all|3|4-5|6-8|9-13}   ← 动画范围与 13 行代码对齐
    ...                          # ① 前缀缓存登记      ← 只出现一次
    ...                          # ② 累计已完成 token   ← 只出现一次
```

## 3. 代码 + 信息框模式

凡是有代码块的 slide，必须配套：

| 元素 | 位置 | 样式 | 内容 |
|------|------|------|------|
| 编号注释 | 代码行尾 | `# ① xxx` | 关键动作标注 |
| 总览框 | 代码下方 | `bg-green-500/10 border-l-3` | 所有步骤一句话总结 |
| 点睛框 | 总览框下方（可选） | `bg-yellow-500/10 border-l-3` | 最关键的一句话总结 |

示例结构：
```
代码块（①②③④ 编号注释）
  ↓
🟢 绿色框：N 个步骤总览
  ↓
🟡 黄色框：关键要点的人话总结（可选）
```

---

## 4. 文本框样式规范

### 4.1 色框使用场景

| 颜色 | 场景 | 类名 |
|------|------|------|
| 绿色 | 总结、观察、好处 | `bg-green-500/10 border-l-3 border-green-500` |
| 黄色 | 注意、警告、约束 | `bg-yellow-500/10 border-l-3 border-yellow-500` |
| 蓝色 | 引导、验证、承接 | `bg-blue-500/10 border-l-3 border-blue-500` |
| 紫色 | 关键结论、联动规则 | `bg-purple-500/10 border-l-3 border-purple-500` |

### 4.2 文字样式

- 引导语/结论文字不要用 `opacity-*` 淡化，应使用色框突出
- `text-xs` 仅用于脚注或极次要信息
- 信息框正文用 `text-sm`，代码块内的注释保持默认

---

## 5. 演讲注释（Speaker Notes）

### 5.1 每页必须有

每个 slide（包括无编号的子 slide）都必须有 `<!-- ... -->` 演讲注释。

### 5.2 内容准确

- 注释必须描述**当前 slide** 的内容，不能是其他 slide 的
- 不能包含编辑指令（如"合并两个紫色框"）
- 不能有重复注释（如结束页两条几乎一样的注释）
- 引用源文件行号必须与 SourceCode 标签一致

### 5.3 反例

```
<!-- 本页用表格展示 status 和 is_prefill... -->  ← 描述的是上一页内容
<!-- 合并两个紫色框，提炼联动规则... -->          ← 编辑指令，不是演讲内容
```

## 7. 内容去重

### 7.1 代码走读与验证脚本之间

第 3 节（代码走读）和第 4 节（验证脚本）容易出现内容重复。处理方式：

- 保留代码走读中的完整内容
- 验证脚本中 **去掉重复的输出表/公式**，改为一行引用指回代码走读

```
反例：§2 页重复输出与 3.4 快速验证一模一样的表格
正例：§2 页保留代码，用一行 "📍 运行结果参见 3.4 快速验证" 替代重复表格
```

### 7.2 代码块与信息框之间

信息框是对代码的"人话总结"，不应与代码注释完全重复。代码注释是操作层面的（"做了什么"），信息框是理解层面的（"为什么这样做 / 关键点是什么"）。

---

## 8. 纵向空间控制

### 8.1 单页代码上限

一个 slide 的代码块不超过 ~15 行。超过时：

1. **按逻辑边界拆分**：如 prefill 循环按"上半段判断 / 下半段执行"拆为两页
2. **去掉冗余展示**：已经在前面出现过的代码不再重复展示
3. **合并同类信息**：两个表达相同意思的框合并为一个

### 8.2 一页最多一张表格

包含表格的 slide，表格是核心元素，不应在同一页再放第二张表格。多表格场景用拆分或左右并排（grid-cols-2）解决。

### 8.3 左右并排适用条件

`grid-cols-2` 左右并排适用于：
- 两张结构相似、都较小的表
- 两张结构不同但都窄于半宽的表
- 不适合列数多、文字长的表

---

## 9. 评审检查清单

逐 slide 检查时使用：

- [ ] 编号存在于教案中？
- [ ] 代码与源文件一致？（变量名、控制流、行号）
- [ ] SourceCode 行号覆盖展示代码？
- [ ] 动画标记 `{all|...}` 行数正确？
- [ ] 代码注释编号每个只出现一次？
- [ ] 信息框与代码注释编号对应？
- [ ] 演讲注释描述的是当前 slide？
- [ ] 内容在第 3/4 节之间无重复？
- [ ] Mermaid 图居中？
- [ ] 单页代码 ≤15 行？
- [ ] 单页表格 ≤1 张？
- [ ] 无 `opacity-*` 淡化的关键文字？
